## Context

AgentCafe currently uses LangGraph to run:

```text
setup -> begin_round -> table_discussion -> collect_round -> rotate_agents -> global_harvest
```

The project-root `proposal.md` proposes a more World-Cafe-faithful architecture:

```text
facilitate_context
-> setup
-> begin_round
-> host_opening
-> table_discussion
-> host_synthesis
-> pocket_generation
-> collect_round
-> rotate_agents
-> global_harvest
```

The architectural challenge is not only prompt quality. It is deciding what context each agent sees, what memory each agent maintains, and what gets routed across rounds.

## Goals

- Encode the strategy in `proposal.md` as OpenSpec requirements.
- Preserve source context as evidence for table discussion.
- Upgrade facilitator from generic question splitter to expert-skill question-setting agent.
- Upgrade table host from summarizer to table-level intrinsic memory maintainer.
- Upgrade speaking agent rotation from reassignment only to reassignment with agent-level migrant memory.
- Upgrade global harvest from summary merger to dual-channel synthesis.
- Add frontend status avatars so users can observe agent-role state dynamics.

## Non-Goals

- No large backend rewrite in the first UI slice.
- No new frontend framework.
- No image asset dependency for avatars.
- No full persistent memory database.
- No direct design solution generation from facilitator or expert skills.

## Core Context Objects

### `source_context`

The uploaded user task/source file.

Rules:

- Facilitator reads it to generate table question settings.
- Table hosts and speaking agents can read it as evidence.
- It is not replaced by facilitator summaries.
- It is not carried from table to table as part of speaking-agent memory.
- If too long, use truncation or retrieval later; do not silently drop it.

### `table_question_plan`

Generated by facilitator.

Contains:

- `context_reading`: user needs, pain points, design tensions, weak signals, possible reframes
- `tables`: per-table proposed configuration

Purpose:

- Prove facilitator has interpreted the source context.
- Provide the rationale for table setup.
- Feed `table_specs`.

### `table_specs`

Generated by facilitator and used as the operational table configuration.

Minimum fields:

- `table_id`
- `expert_skill`
- `expert_rationale`
- `lens`
- `guiding_question`
- `why_this_matters`
- `evidence_basis`
- `avoid_solution_bias`
- `round_subquestions`

Compatibility:

- Existing `table_questions` can be derived from `table_specs[table_id].guiding_question`.

### `table_memory`

Generated and updated by table host.

Design:

- Fixed shell for table id, round, guiding question, source anchors.
- LLM-generated inner table-memory template.
- Host-generated table memory.
- Pattern delta across rounds.
- Next-round question seeds.

Why dynamic:

- Fixed hand-written fields can flatten hidden shifts in discussion.
- The host needs to notice how the table's understanding evolves by round and group composition.

### `carry_over_packet`

Generated for a speaking agent after a round and routed to its next table.

Design:

- Fixed shell for routing:
  - `agent_id`
  - `from_table`
  - `to_table`
  - `after_round`
  - `current_table_task_anchor`
- Dynamic inner memory:
  - `memory_update_instruction`
  - `llm_generated_memory_template`
  - `agent_generated_memory`
  - `bridge_intent`

Rules:

- It is agent-level migrant memory.
- It is not table memory.
- It is not a full transcript.
- It should help the speaking agent test differences and connections at the next table.

## Agent Role Design

### Facilitator

Prompt responsibilities:

- Read user request and source context.
- Perform expert-skill routing.
- Use expert skills to generate table configurations.
- Calibrate questions against World Cafe standards.

Expert-skill routing:

- `lou-yongqi`: social innovation, sustainability, service systems, urban-rural interaction.
- `wang-meng`: Design x AI, KG/LLM, multimodal KG, intelligent interaction.
- `liu-long`: human factors, inclusive design, user research, usability, trust.
- `wang-shouzhi`: design history, theory, education, context, critique.

Output:

- Strict JSON `table_question_plan`.
- Derived `table_specs`.

### Table Host

Prompt responsibilities:

- Stay neutral.
- Maintain table-level intrinsic memory.
- Use LLM-generated template strategy to update memory.
- Generate host opening and dynamic round subquestions.
- Preserve repeated themes, minority views, unresolved tensions, weak signals, and unfinished questions.
- Remove redundant explanations and social filler.

The host is not a normal speaking participant.

### Speaking Agent

Prompt responsibilities:

- Speak naturally from profile and current table context.
- Use `carry_over_packet` without mechanically reciting it.
- Distinguish previous-table personal insight from current-table emerging views.
- Look for difference, analogy, tension, or opportunity across tables.
- Avoid full solution generation.

### Rotation

Code responsibilities:

- Keep hosts fixed.
- Move non-host speaking agents to the next table.
- Route each speaking agent's packet to its next table.
- Record rotation history.

Rotation must not generate insight.

### Global Harvest

Prompt responsibilities:

- Cluster cross-table patterns.
- Identify weak signals.
- Recognize tensions.
- Generate opportunity hypotheses and reframed questions.
- Suggest next learning experiments.

## LLM-Generated Template Strategy

The change follows the strategy discussed in `proposal.md`: avoid over-specified hand-written inner memory templates.

Implementation pattern:

1. Keep route-critical fields fixed.
2. Generate a role-specific memory update instruction.
3. Generate a context-specific memory template.
4. Fill the template with role-generated memory.
5. Preserve a natural-language thick-description or bridge-intent field where implicit meaning matters.

Use this strategy for:

- `table_memory`
- `carry_over_packet`

Do not use this strategy for:

- route IDs
- table IDs
- agent IDs
- round indexes
- assignment maps

## Frontend Status Avatar Design

The frontend status dock should be a thin operational display:

- Facilitator avatar tracks question-setting and setup.
- Host avatar tracks table memory/opening/host records.
- Speaking avatar tracks discussion and contributions.
- Rotation avatar tracks movement between rounds.
- Harvest avatar tracks global synthesis.

Data source:

- Existing run stream events.

No backend change is required for the first UI slice.

## Risks And Mitigations

- Risk: Dynamic templates become hard to parse.
  - Mitigation: Keep fixed shells and parse only required shell fields.

- Risk: Expert-skill routing over-specializes tables.
  - Mitigation: Facilitator performs final World Cafe calibration and can mark `expert_skill` as `mixed`.

- Risk: Source context overwhelms table prompts.
  - Mitigation: Start with current truncation behavior, then add retrieval-style source selection later if needed.

- Risk: Status avatars add visual noise.
  - Mitigation: Show only one concise latest update per agent role.
