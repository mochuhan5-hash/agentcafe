# Change: Update Agent Context Orchestration

## Source Strategy

This OpenSpec change implements the architecture strategy documented in the project-root `proposal.md`.

That strategy treats AgentCafe as a World Cafe context-flow system rather than a generic multi-agent chat. The key claim is:

> Agent optimization includes both prompt optimization and context management. Facilitator question setting is prompt-level optimization; table memory, carry-over packets, rotation routing, and harvest are context-management mechanisms.

## Why

The current system can run a multi-table discussion, but its agent roles are still too close to fixed prompt wrappers:

- The facilitator generates table questions without explicit expert-skill routing.
- Table host memory is closer to a Markdown summary than evolving table-level intrinsic memory.
- Speaking agents rotate, but they do not carry agent-level migrant memory into the next table.
- `rotate_agents` moves agents but does not yet route carry-over packets.
- Global harvest can merge summaries, but the desired strategy requires explicit Pattern Channel and Weak Signal Channel analysis.
- The frontend shows outputs, but not the evolving state of each agent class.

This change proposes a phased architecture update so the World Cafe mechanics are represented in state, prompts, memory objects, and UI.

## What Changes

### 1. Facilitator Expert-Skill Question Setting

The facilitator will first inspect the user request and uploaded task/source file, then perform expert-skill routing before generating table configurations.

Available expert skills:

- `lou-yongqi`: design-driven innovation, social innovation, sustainability, service/system design, urban-rural interaction.
- `wang-meng`: Design x AI, KG/LLM, multimodal knowledge graph, intelligent interaction, technical system translation.
- `liu-long`: human factors, inclusive design, user research, medical usability, trust, co-design.
- `wang-shouzhi`: design history, theory, education, cultural context, housing/residential critique, value judgment.

The facilitator remains responsible for World Cafe quality calibration: questions must be evidence-supported, open, generative, non-leading, and able to travel well across tables.

### 2. Table Question Plan And Table Specs

The facilitator will produce a `table_question_plan` and per-table `table_specs`, not only raw question strings.

Each table spec will include:

- `table_id`
- `expert_skill`
- `expert_rationale`
- `lens`
- `guiding_question`
- `why_this_matters`
- `evidence_basis`
- `avoid_solution_bias`
- `round_subquestions`

The uploaded source context remains a discussion basis for table hosts and speaking agents. The facilitator's context reading does not replace the original source.

### 3. Table Host Intrinsic Memory

`table_memory` will become table-level intrinsic memory maintained by the table host.

It will use a fixed shell plus LLM-generated table memory templates:

- fixed shell: table id, round, guiding question, source anchors
- dynamic template: host-generated dimensions based on current table context
- generated memory: host-generated table memory
- pattern delta: how the table's understanding changed from prior rounds
- next question seeds: dynamic subquestions for the next round

The host should track repeated themes, minority views, unresolved tensions, weak signals, low-value archive candidates, and changes in the table's understanding across rounds.

### 4. Dynamic Host Openings And Round Subquestions

Before each round, the table host will generate an opening and subquestions from the previous `table_memory`.

Round scaffold:

- Round 1: divergent observation
- Round 2: connections and tensions
- Round 3: problem reframing

The scaffold is not a fixed question template. Concrete subquestions are generated by the host using LLM-generated template strategy.

### 5. Speaking-Agent Carry-Over Packets

`carry_over_packet` will become agent-level migrant memory.

It is not copied table memory and not a full transcript. It will use:

- fixed route shell: `agent_id`, `from_table`, `to_table`, `after_round`, `current_table_task_anchor`
- `memory_update_instruction`
- `llm_generated_memory_template`
- `agent_generated_memory`
- `bridge_intent`

This follows the LLM-generated template direction from the intrinsic memory paper: avoid brittle hand-written inner fields and let the LLM generate a context-appropriate personal memory template.

### 6. Rotation As Routing Infrastructure

`rotate_agents` will remain a routing mechanism:

- keep table hosts fixed
- rotate speaking agents
- route generated carry-over packets to the next table

It must not generate or reinterpret packet contents.

### 7. Global Harvest Dual-Channel Analysis

Global harvest will explicitly separate:

- Pattern Channel: repeated cross-table themes and collective patterns
- Weak Signal Channel: rare, high-tension, high-novelty, promising minority insights

It will also identify cross-table tensions, opportunity hypotheses, reframed questions, and next learning experiments.

### 8. Frontend Agent State Avatars

The frontend will expose each agent class as an operational avatar:

- Facilitator
- Table Hosts
- Speaking Agents
- Rotation
- Global Harvest

Hover/focus on an avatar will reveal the latest status update for that role.

## Phasing

### Phase 1: Spec And UI Surface

- Create detailed OpenSpec proposal.
- Add frontend role avatars and hover status cards using existing stream events.

### Phase 2: Facilitator Upgrade

- Add expert-skill routing prompt strategy.
- Expand facilitator output to `table_question_plan` and `table_specs`.
- Preserve compatibility with existing frontend question editing.

### Phase 3: Table Host Memory Upgrade

- Replace fixed Markdown summary memory with dynamic table-level intrinsic memory.
- Add host opening and question seed generation.

### Phase 4: Carry-Over Packet Upgrade

- Add pocket-generation step.
- Generate LLM-template-based agent migrant memory.
- Route pockets through `rotate_agents`.

### Phase 5: Global Harvest Upgrade

- Add dual-channel harvest prompt/output.
- Render or transform JSON harvest into frontend Markdown.

## Non-Goals

- Do not make table hosts ordinary participants.
- Do not let speaking agents carry complete previous-table transcripts.
- Do not make `rotate_agents` an insight generator.
- Do not use facilitator summaries as a replacement for uploaded source context.
- Do not make expert skills generate final design solutions.

## Open Questions

- Should expert skill routing load local skill files at runtime or use a distilled routing prompt embedded in facilitator prompt?
- Should source context be truncated uniformly or selected by retrieval per table?
- Should host process interventions become explicit stream events?
- Should carry-over packet generation be performed directly by each speaking agent, or by a dedicated node that prompts the speaking-agent perspective?
- Should global harvest output be stored as JSON first and rendered to Markdown second?
