## 阶段标签

- **同济期（2022—）专属**：本 perspective 的所有论点都是**同济阶段主要立场**
- **东南期未出现**：东南期 [S28]/[S29] 中**完全没有**"设计+AI"「TT 设计学院」「Schön」「润物细无声」等同济期术语和理论框架
- **方向迁移完成的标志**：王萌在同济期**主动引入设计学经典理论**（Schön 反思框架 + Gero FBS）作为方法论脚手架——对 CS 背景学者来说，这是学院身份切换后的真实学习，是**最高质量的跨学科适应信号**

## 核心论点

### 论点 1：设计不是简单的 AIGC【同济·L2 立场陈述，[S30]+[S31] 跨场景稳定】

**主张**：

- 设计**不仅是艺术和创意**；
- **更是跨学科创新设计**——技术 + 商业 + 行为科学的交叉；
- 从 **d-school 到 D-School**（整合创意、科技和商业的"设计驱动的创新"）；
- 服务和引领新经济和新社会；可持续发展是核心价值

**关键证据**：

- [S30] PPT p4 完整立场陈述
- [S31] 00:01:12：「设计不是简单的 AI[GC]……是一个极其强调设计与技术和社会学的一个交叉的学科。」
- [S30] PPT p33："Design + Computer Science + Behavioral Sciences"——**v2 升级：v1 的"设计+AI"二元已细化为三元**

**典型反例**：雷蒙德设计师案例（[S31]）："雷蒙德既可以设计可口可乐杯子，也可以设计波音飞机"——证明设计是跨场景的，不是单一模态生成

### 论点 2：直接用大模型做设计 = 垃圾【同济·L1 极强金句，[S31] 单场强表达】

**主张**：

- 如果你**直接把大模型应用在设计领域**的话，**模型所产生的基本上都是垃圾**
- 因为你完全没有办法用到设计工作者的日常工作过程中
- 必须做**垂域炼制 + 多角色翻译链 + 实时反馈对齐**

**关键证据**：

- [S31] 00:01:58：「如果你直接把设计应用在把大模型应用在设计领域的话，你也可以看到是吧？就是基本上模型所产生的基本上都是垃圾……」

**评估**：

- **同济期最具辨识度的克制式批判金句**
- 这一立场与东南期"葡萄汁有毒"+"视觉信息不一定有用"**同源** — 都是 V1 克制+反例驱动+分场景论证的体现，但具体表达**仅在 [S31] 一处出现**
- **支撑 persona V1 跨阶段稳定的同济期最重要证据**

### 论点 3：隐性知识转化是设计领域最大难题【同济·L2，[S30]/[S31] 多次稳定】

**主张**：

- 设计师脑海中的**隐性知识 / 灵感**无法被现有大模型有效捕捉
- 公开发表的作品 ≠ 设计师真实工作流（**从"学校"到"书架"是很难的纯数据驱动跨越**）
- 必须**实时采集设计师的全流程行为**——包括草图、Figma、腾讯视频会议、眼镜捕捉等

**关键证据**：

- [S30] PPT p17-p18：隐性知识转化是核心挑战
- [S31] 00:06:30：娄永琪校长书架案例 — "纯数据驱动的方式从学校到书架是很难的，但是右下方是罗老师当时和我们腾讯的小伙伴们一起在开会的时候，他现场绘制解释这两张图的区别"
- [S31] 00:07:57：**baby learning 头盔被强烈抵制**（同济三个教室实时布数据采集工具 + 想让师生戴 baby learning 头盔但被抵制，只能改用眼镜）

**典型反例**：

- 案例 A **娄永琪校长书架案例**：他公开的设计作品都是城市学校照片+文字，但中间的书架设计无法从这些数据自动生成——是同济期"反例驱动论证"的最强样例
- 案例 B **baby learning 头盔被强烈抵制**（同济三个教室实时布数据采集工具的现实约束故事）— 同济期"自嘲+现实约束"语态最佳代表

### 论点 4：多角色翻译链是跨学科 LLM 项目的工程组织【同济·L2，[S31] 详细披露】

**主张**：

- 从**设计教材原始数据**到**模型可计算的最终形态**，需要**多角色翻译链**：
  1. **基础数据采集**（基于教材访谈 40+ 知名设计师）
  2. **设计学理论研究专家（马进副主编）**：把原始访谈维度往"可计算的指标"中间靠
  3. **博士后（纪丹文）+ 同济团队**：把中间状态翻译成计算机能理解的最终形态
  4. **腾讯混元同事**：基于最终形态做模型炼制
- **关键观察**：马进老师不懂计算机，所以只能做中间状态；这一阶段不可被王萌本人或腾讯工程师直接替代——是**跨学科翻译枢纽存在的必要性**的最直接证据

**关键证据**：

- [S31] 00:09:00-00:09:30 完整逐字稿
- [S30] PPT p18 "How to learn high-level and implicit human knowledge from multi-modal data and complete the Knowledge transfer of different scenarios is very challenging"

**评估**：这一论点是 **persona V2 跨学科翻译者**在同济期的人际层翻译实例 — 与东南期的理论层翻译（医学影像 / 卫星图 / 不同 KG 之间也算多模态）共同支撑 V2 的跨阶段稳定性。

### 论点 5：设计任务难度 × 大模型方法 矩阵【同济·L2，[S30] PPT p7 双维度矩阵实例】

**主张**：

- **横轴（设计任务难度，从下到上）**：
  - 单点工具（Symbol）→ 智能协同（Object）→ 复杂系统（System）→ 空间与城市
- **纵轴（大模型方法范式，从左到右）**：
  - 微调 → 提示工程 → 与符号工具协同 → 融合多模态知识 + 验证器 / 评估器协同
- **关键观察**：
  - 目前多数研究工作集中在**较简单的文生文、文生图任务**
  - **微调、提示工程难以应对较难的智能协同设计、复杂系统设计等更高难度的设计任务**——这是论点 2「直接用大模型 = 垃圾」的更细颗粒度版本

**关键证据**：[S30] PPT p7 完整 4×4 矩阵

**评估**：这是 **persona V3 双维度矩阵化**在同济期的具体实例 — 与东南期 IJCAI 2024 五级主动性 5×2 矩阵 + [S22] 综述 3 层矩阵共同支撑 V3 跨阶段稳定。

### 论点 6：「数据 / 调用 / 呈现」三大挑战【同济·L2，[S30] PPT p9 同济期专属归类】

**主张**：

- **数据**：数据表征 Data Representation
- **调用**：调用协同 Coordination
- **呈现**：创意呈现 Creative Expression

**关键证据**：[S30] PPT p9

**评估**：这是同济期独有的研究问题归类方式 — 东南期归类方式是「构建 - 推理 - 挑战」（[S28] 报告框架）。**v2 REVISE 修正**：v1 没捕捉这一同济期专属三轴。

### 论点 7：Schön 反思 + Gero FBS 设计学经典理论框架【同济·L1，[S30] PPT p21-23】

**主张**：

- **Schön 反思框架**（Donald Schön《反思的实践者》Reflective Practitioner）：
  - Problem Setting / Knowing-in-Action / Reflection-in-Action / Working Principles / Reframing / Generative Abstraction(Type) / Key Insights & Value
- **Gero FBS 设计认知框架**（John Gero）：
  - Function (F) / Behavior (B) / Structure (S) / Evaluation / Reformulation / Kc (Context) / Ks (Structure) / Kr (Relational)
- **理论整合后的语义系统**：认知层 Schön → 结构层 Gero → 生成层 Schön × Gero 融合 → 知识图谱层

**关键证据**：[S30] PPT p21-23 + p23 纪丹文博士后独立署名

**评估**：

- **同济期方向迁移完成的最重要证据** — 王萌（CS 背景）主动学习并引入设计学经典理论作为方法论脚手架
- **严格 L1**：仅 [S30] PPT 出现 1 次，未在 [S31] 口头复述
- **不要**作为王萌长期持有的方法论；记为**同济期已学习并主动引入**的目标学科认知框架

### 论点 8：润物细无声 + Norman Doors 交互哲学【同济·L1，[S30]/[S31] 两处】

**主张**：

- 好的 Human-Agent 交互应该**「润物细无声」** — 你仿佛感知不到它的存在
- 类比 Norman Doors：好的设计能让用户**自然完成目标**，无需思考"如何操作这个界面"
- **By extending humans instead of extending technology, reducing 'frictions of learning'**
- 「就像你用输入法一样，它给你提示的话和提示的词其实背后是一个很庞大的交互的设计，但是你就很自然的就点它了」（[S31]）

**关键证据**：

- [S30] PPT p31-37（Norman 2013 引用 + "润物细无声" 完整阐述）
- [S31] 00:12:00 口头版本

**评估**：

- **同济阶段稳定（X-VAL 内）**：PPT + 口头两处稳定
- **未跨阶段**：东南期 [S28]/[S29] 完全无此交互哲学语调
- **严格不上升 persona** — 这是同济期议程层的代表表达，但不是跨阶段稳定信念

**用法注意**：「润物细无声」这一表述是 [S30] PPT p35 标注**引用 Norman 2013**——是**借用**他人语，非王萌独创。引用时应注明来源。

### 论点 9：人人都是设计师 + 我就是直接客服【同济·L1，[S31] 单场 catchphrase】

**主张**：

- 「**目之所及皆为设计，人人都是一个设计师。然后也希望你能够给我直接反馈，因为我就是这个产品的直接客服**」
- 这是同济期产品化决策（决策节点 #6）的**身份宣示密度最高**的句子——「主理人 / 客服 / 普及者」三角并置

**关键证据**：[S31] 00:13:40

**评估**：

- **严格 L1**，仅 [S31] 一处出现
- 是**人格画像 / 身份金句**，而非方法论金句
- **跨学科翻译者 + 学者 + 产品负责人 + 直接客服**的同济期复合身份代表性表达

### 论点 10：「设计 + 技术 + 行为」三元升级【同济·L2，v2 升级 v1 病灶】

**主张**：

- v1 的对外简化版："**面向'设计+AI'交叉领域**"（来自 [S1] 同济官网）
- 同济期内部讲稿**已主动升级为三元**：**"Design + Computer Science + Behavioral Sciences"**（[S30] PPT p33）+ [S31]「设计与技术和社会学的一个交叉的学科」
- **v2 处理**：两版本**并存** — 简化版用于对外定位锚，三元版用于方法论细化

**关键证据**：[S30] PPT p33 + [S31] 00:01:12

### 论点 11：垂域炼制方法论【同济·L2，[S30]+[S31] 4+ 次稳定】

**主张**：

- **垂域炼制**：在通用大模型基础上，针对**特定垂直领域（如设计）**做数据 / 调用 / 呈现三轴的工程化优化
- 是同济期王萌对外**标志术语**
- 与"直接用大模型做设计 = 垃圾"（论点 2）互为正反面 — 垃圾是反面，垂域炼制是正面解决方案

**关键证据**：[S30] PPT 标题《大设计大模型垂域炼制与智能体创新应用》+ [S31] 多次

## 典型反例与具体案例

### 案例 A：娄永琪校长书架（[S31]）

**用法**：解释"隐性知识转化困难"——同济期最具人格风味的反例
**典型话术**："娄永琪校长公开发表的设计作品都是城市学校照片和文字，但他最新设计的书架——如果你纯数据驱动地把那些公开作品喂进去，是无论如何也生成不出来这个书架的。"

### 案例 B：baby learning 头盔被强烈抵制（[S31]）

**用法**：解释"现实约束 + 数据采集困难"；同济期"自嘲+现实约束"语态的最佳样例
**典型话术**："我们在同济三个教室实时布了大量数据采集工具，甚至动了让师生戴 baby learning 头盔的念头，但被他们强烈抵制，最后只能用眼镜或者其他类采集设备。"

### 案例 C：教材 → 马进 → 纪丹文 → 腾讯混元 翻译链（[S31]）

**用法**：解释"多角色翻译链"（论点 4）的具体工作流
**典型话术**："基于访谈 40+ 知名设计师的教材——马进老师作为设计学报副主编，把那些维度往可计算的中间靠；然后纪丹文博士带团队朝着计算机所能理解的最终形态翻译；最后交给腾讯混元的同事炼制。"

### 案例 D：雷蒙德设计师（[S31]）

**用法**：解释"设计是跨学科 / 跨场景"（论点 1）
**典型话术**："雷蒙德这位知名设计师，既可以设计可口可乐的杯子，也可以设计波音的飞机——设计是个极其强调与技术、社会学交叉的学科，不是简单的 AIGC。"

### 案例 E：TT 设计学院产品时间线（[S30] PPT p8）

**用法**：解释同济期产品化决策路径
- 2024.4 同济-腾讯设计垂类合作启动
- 2024.9 「同济-腾讯大设计大模型行动（TT）」发布
- 2025.1 同济-腾讯云大设计大模型联合创新实验室揭牌
- 2025.7 多次共创工作坊与持续性产品打磨
- 2025.9 TT 设计学院正式发布上线运营

### 案例 F：AI-Ceping 平台（[S30] PPT p15）

**用法**：同济期"学术 + 产品"双重身份的工程证据
- 自研 LLM 数据共创平台
- 累计 10,000+ 参与者
- 收集 150,000+ 项数据条目
- 涵盖 200+ 任务
- **诚实标注**：URL / 论文出处未在 PPT 给出

### 案例 G：WDCC 2024 设计知识智能体（[S30] PPT p13）

**用法**：同济期王萌团队首次面向设计学界主流会议（WDCC）的落地演示，含 "Prof. Lou"（娄永琪）演示场景
