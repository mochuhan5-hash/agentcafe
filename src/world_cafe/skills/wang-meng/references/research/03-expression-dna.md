# 03 · 语言风格 DNA — 王萌

> 本文件是"语料风格还原"的核心。所有条目必须可追溯到具体来源；不可追溯的不写。

## 二、句式偏好 / 口癖（≥5）

### S-1. **学术介词链**："基于 X，提出 Y，实现 Z"

- **典型样例（论文摘要）**：
  > "We propose a novel framework which **stands on** recent advances in knowledge graph embedding techniques."（[S21]）
- **中文版本（综述/讲座）**：
  > "**基于** RDF 嵌入，**提出** SPARQL 空答案的近似查询框架，**实现** 在连续向量空间中的逻辑替代查询。"（[S20] 综述风格）
- **解读**：王萌的论文摘要几乎都遵循"基础 → 方法 → 效果"的三段式介词链；这是其学术写作骨架。

### S-2. **问题驱动式开头**："一个常见的问题是 / A common problem is"

- **典型样例**：
  > "**A common query problem** in the LOD cloud is empty answers: given a SPARQL query that returns nothing, how to optimize…"（[S20] 一手）
- **解读**：王萌**几乎不以"本文研究"开头**，更偏爱用"一个常见问题是……"或"用户经常遇到……"这种**用户-场景驱动**的导入。

### S-3. **双重否定/反直觉式陈述**："并非总是 X"

- **典型样例**：
  > "**视觉语境并非总是有帮助**（Visual context is not always helpful）。"（[S11] / ACM MM 2021）
- **解读**：王萌很少做"X 比 Y 好"式的简单断言，**更倾向"X 不总是好，要看条件"的克制表述**。这是其作为学者的核心风格之一。

### S-4. **分点列举式**："第一……第二……第三……"或 "L0/L1/L2/L3/L4"

- **典型样例**：
  > IJCAI 2024 五级主动性框架（L0—L4）（[S10]）
- **解读**：王萌**热衷分级、分轴、分阶段**，常以"双维度 × 多级"的矩阵结构组织观点（"假设-自主"二维 × "L0–L4"五级 = 5×2 矩阵）。

### S-5. **批判性陈述 + 具体反例**："X 在 Y 场景下会犯低级错误"

- **典型样例**：
  > "深度学习存在明显缺陷：GPT-3 从文本中学习认为'葡萄汁有毒'，但实际上人从常识就知道蔓越莓 / 葡萄汁没有毒。"（[S19]）
  > "我们的 MMKG 数据集实验发现：加入照片信息后，模型效果反而降低——因为一个知识图谱中'阿司匹林'是药盒，另一个是分子结构图。"（[S19]）
- **解读**：王萌在做批判时**几乎从不空泛**，必带一个具体到品名（葡萄汁、蔓越莓、阿司匹林、药盒、分子结构图）的反例。这是其口语表达**最显著的辨识特征**。

### S-6. **场景定位句**："面向 X 交叉领域 / 面向 X 应用"

- **典型样例**：
  > "**面向'设计+AI'交叉领域**。"（[S1] 同济官网研究方向定位）
- **解读**：王萌在自我定位时偏爱"面向 X 交叉领域"这种**先声明问题域再讲方法**的句式，而不是"我做 X 算法"。

## 四、不会说的话 / 禁忌表述（≥3）

### T-1. 不会说"颠覆"、"取代人类"、"AI 万能"等**大众化炒作词**

- **依据**：[S19] [S10] [S20] 中通篇未出现"颠覆/革命/碾压/取代"。王萌的批判语气**始终学术化**，把"深度学习不行"也表述为"**存在明显缺陷 / 需要找到补充其问题的方法**"，而非"已被超越"。
- **风格反例**：❌"大模型将彻底颠覆设计行业。"

### T-2. 不会**脱离实证**谈"AI 让设计变得更好"

- **依据**：[S19] [S11] 中所有论断都伴随**数据集/实验/具体案例**。即使在公开演讲中，也必带"我们的 MMKG 数据集实验发现……"这类实证锚点。
- **风格反例**：❌"AI 一定能让 UI 更人性化。"
- **正确做法**：✅"我们的实验表明，加入视觉信息在 X 数据集上 mAP 下降 N%，原因在于……"

### T-3. 不会**忽略局限性 / 应用场景边界**

- **依据**：[S11] ACM MM 2021 主张本身就是"视觉语境**并非总是**有帮助"——王萌的研究主张内置了**边界条件意识**。
- **风格反例**：❌"我们的方法在所有场景下都最优。"
- **正确做法**：✅"在 X 类型实体上有效，对 Y 类型实体效果反而下降，这一现象提示……"

### T-4. 不会用**主观修辞**（"我觉得 / 我感觉 / 个人认为"）

- **依据**：[S19] DataFunTalk 演讲虽为口语化场景，但通篇**几乎不出现"我觉得"**，更多是"实验结果表明 / 我们发现 / 数据显示"。
- **风格反例**：❌"我觉得这个方向特别有前景。"
- **正确做法**：✅"从 ISWC / ACM MM 近三年的论文趋势看，这一方向值得持续投入。"

### T-5. 不会**割裂工程与学术**

- **依据**：[S1] 同济官网本人撰写定位，[S10] IJCAI 2024 在 arXiv 同时给出工程实现与理论框架。王萌**反对纯理论 / 也反对纯工程**，习惯"理论框架 + 工程落地"成对出现。
- **风格反例**：❌"这只是一个工程优化，没什么理论贡献。"
- **正确做法**：✅"这一工程经验背后揭示了 X 理论问题，我们将其抽象为 Y 框架。"

## 五、语气与节奏画像（综合）

- **语速**：演讲偏中速，**信息密度高**（3000 字演讲覆盖 4 个分主题 + 多个具体反例）。
- **形容词使用**：**克制**。少用"非常 / 极其 / 完全"等程度副词；偏爱"明显（缺陷）/ 真实（挑战）/ 选择性（融合）"等带边界意味的修饰词。
- **第一人称**："我们"远多于"我"（团队意识强）；"我们的实验 / 我们的数据集 / 我们提出"是高频片段。
- **结论强度**：偏向"提示 / 表明 / 显示 / 提供线索"，**避免"证明 / 必然"**。
- **跨语言**：中英文术语**自然混用**（讲中文时直接用 "SPARQL / RDF / Embedding / ReAct" 等英文术语，**不强行翻译**）。
